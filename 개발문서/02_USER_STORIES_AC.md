# NH뚝딱협업스튜디오 User Stories & Acceptance Criteria v1.0

## Epic E1. 인증/업무공간
### US-001 SSO 로그인
**As a** 사내 사용자
**I want** SSO로 로그인하고
**So that** 별도 계정 없이 서비스를 이용하고 싶다.

**AC**
- Given 사내 SSO 인증 성공, When 서비스 접속, Then 사용자 계정과 기본 권한이 생성/조회된다.
- 인증 실패 시 서비스 API가 보호된다.
- 브라우저에 LLM Token이 노출되지 않는다.

### US-002 프로젝트 생성
**As a** 업무 담당자
**I want** 업무 단위 프로젝트를 생성하고 멤버를 초대하고 싶다.

**AC**
- 프로젝트명/설명/소유자를 입력해 생성할 수 있다.
- 멤버별 권한을 구분할 수 있다.
- 모든 주요 변경은 History에 남는다.

## Epic E2. NH 업무자산
### US-010 Template 선택
**As a** 업무 담당자
**I want** NH Template을 선택해 결과물에 적용하고 싶다.

**AC**
- NH 공통 Template과 개인/부서 Template이 구분된다.
- Template 버전을 선택할 수 있다.
- 사용할 Template이 AI 요청 컨텍스트로 전달된다.

### US-011 참고자료 등록
**As a** 업무 담당자
**I want** 기존 자료를 프로젝트에 등록하고 AI가 참고하도록 하고 싶다.

**AC**
- 허용된 파일 형식과 크기 정책을 적용한다.
- 파일은 프로젝트와 연결된다.
- AI 요청 시 사용자가 참조 여부를 선택할 수 있다.

### US-012 브랜드 자산 선택
**As a** 업무 담당자
**I want** NH 로고·색·서체 자산을 골라 시안에 반영하고
**So that** 디자인을 몰라도 결과물이 NH답게 나오길 원한다.

**AC**
- 브랜드 자산은 Template의 한 유형(`BRAND_ASSET`)으로 조회된다.
- 선택한 자산이 AI 요청 컨텍스트로 전달된다.
- 자산이 하나도 없어도 생성은 가능하되, NH 색·로고가 반영되지 않는다는 안내가 표시된다.
- 로고·캐릭터 등 그림 요소는 선택된 자산만 사용되며 AI가 새로 생성하지 않는다.

## Epic E3. AI 제작
### US-020 AI 초안 생성
**As a** 업무 담당자
**I want** 채팅으로 업무 내용을 설명해 문서/화면 초안을 만들고 싶다.

**AC**
- 요청/참고자료/Template을 기준으로 AI 작업이 생성된다.
- LLM API 호출 실패 시 사용자에게 작업 상태와 재시도 방법이 표시된다.
- 완료된 결과는 프로젝트와 연결된다.

### US-021 비동기 AI 작업
**As a** 사용자
**I want** 긴 AI 작업도 화면을 닫지 않고 처리되길 원한다.

**AC**
- 작업은 REQUESTED/PROCESSING/COMPLETED/FAILED 상태를 가진다.
- 실패한 작업은 원인 요약과 재시도 옵션을 제공한다.
- 중복 제출을 방지한다.

### US-022 브랜드 시안 생성
**As a** 카드 상품 기획자 / 마케팅 담당자
**I want** 카드나 홍보물의 시안을 서로 다른 방향으로 여러 개 받아
**So that** 회의에서 방향을 눈으로 놓고 정하고 싶다.

**AC**
- 산출물 유형(카드 실물 / 홍보물)과 규격 프리셋을 선택할 수 있다.
- 브리프(상품·캠페인명, 타겟, 전달할 느낌, 필수 문구)를 디자인 용어 없이 입력할 수 있다.
- Given 브리프와 자산이 입력됨, When 생성을 요청, Then 서로 다른 방향의 시안 3개가 하나의 AI 작업으로 생성된다.
- 각 시안에는 방향을 설명하는 라벨이 함께 제공된다.
- 일부 시안만 실패한 경우 성공한 시안은 그대로 표시되고 실패분만 재시도할 수 있다.
- 생성 시점에는 Version이 만들어지지 않는다.

### US-023 시안 비교·선택
**As a** 프로젝트 담당자
**I want** 시안 3개를 나란히 놓고 의견을 모은 뒤 하나를 확정하고
**So that** 왜 그 방향으로 갔는지가 기록으로 남길 원한다.

**AC**
- 3개 시안이 규격 비율을 유지한 채 나란히 표시된다.
- 시안별로 의견을 등록할 수 있고, 의견은 해당 시안에 귀속된다.
- Given 3안이 표시됨, When 하나를 선택, Then Version 1개가 생성되고 선택되지 않은 시안은 Version이 되지 않는다.
- 생성된 Version은 `source_type = AI_GENERATION`과 원 AI 작업(`source_job_id`)에 연결된다.
- 선택 이유를 선택적으로 남길 수 있으며, 남기면 Version 요약과 History에 함께 기록된다.
- 선택되지 않은 시안도 검토 후보로 조회 가능한 상태를 유지한다.

## Epic E4. 협업/의사결정
### US-030 의견 등록
**As a** 검토자
**I want** 결과물에 의견을 남기고 싶다.

**AC**
- 일반 의견과 특정 영역/요소에 대한 의견을 구분할 수 있다.
- 작성자와 작성시각이 기록된다.
- 담당자에게 알림할 수 있는 확장 포인트를 둔다.

### US-031 AI 의견 취합
**As a** 프로젝트 담당자
**I want** AI가 여러 의견을 합의/이견/추가확인으로 정리해주길 원한다.

**AC**
- 원 의견과 AI 요약 결과의 연결관계를 보존한다.
- AI 결과는 제안이며 자동 확정되지 않는다.
- 분류되지 않은 의견은 누락되지 않아야 한다.

### US-032 반영 결정
**As a** 담당자
**I want** 제안된 의견을 선택해서 반영하고 싶다.

**AC**
- 각 의견에 대해 반영/보류/반려를 선택할 수 있다.
- 결정 이유를 선택적으로 기록한다.
- 선택된 의견을 기준으로 AI 수정 작업이 생성된다.

### US-033 책임성 검토
**As a** 담당자
**I want** 만들어진 화면이 사회적·윤리적으로 문제가 될 만한 지점을 미리 알고 싶다.

**AC**
- 목업이 생성되면 표현·차별 / 금융소비자보호 / 다크패턴 / 접근성 네 축의 검토가 **자동으로 실행된다.**
- 각 지적은 **목업에서 그대로 인용한 근거**를 포함한다. 근거가 없는 지적은 표시되지 않는다.
- AI는 적법성을 **판정하지 않는다.** "위법/적법" 같은 판정 표현이 결과에 나타나지 않는다.
- 각 지적에 대해 **반영 / 보류 / 반려 / 준법 검토 요청** 중 하나를 선택할 수 있고, 누가·언제 결정했는지 남는다.
- 금융소비자보호 축의 지적은 `준법 검토 요청` 경로가 강조된다.
- 지적할 항목이 없으면 없다고 표시된다. 억지로 채우지 않는다.
- 검토 결과는 화면을 막지 않는다. Export·공유는 지적이 남아 있어도 가능하다.
- 담당자가 수동으로 다시 검토할 수 있으며, 재실행은 이전 결정을 덮어쓰지 않는다.

### US-034 UX 리스크 검토
**As a** 담당자
**I want** 우리가 나눈 논의대로 가면 사용자가 불편해지는 지점이 없는지 확인하고 싶다.

**AC**
- 검토는 **담당자가 요청할 때만** 실행된다. 댓글이 달릴 때마다 자동으로 끼어들지 않는다.
- AI는 **전 화면의 목업과 의견 전문을 함께** 읽는다. 화면 한 장만 보고 판단하지 않는다.
- 각 지적은 기획안·목업·의견에서 **그대로 인용한 근거**를 포함한다. 원문에 존재하지 않는 인용만 달린 지적은 표시되지 않는다.
- AI는 품질을 **판정하지 않으며**, 특정 의견이나 작성자를 지목해 틀렸다고 말하지 않는다.
- 지적은 **의견 목록에 사람 댓글과 시간순으로 섞여** 표시되고, `AI` 표기로 사람 의견과 구분된다.
- 각 지적에 대해 **반영 / 보류 / 반려** 중 하나를 선택할 수 있고, 누가·언제 결정했는지 남는다.
- 지적할 항목이 없으면 없다고 표시된다. 억지로 채우지 않는다.
- 재실행은 이전 검토와 결정을 덮어쓰지 않는다.
- AI 카드가 섞여도 캔버스 메모 핀 번호는 사람 댓글 기준을 유지한다.

## Epic E5. Version/History
### US-040 Version 생성
**As a** 담당자
**I want** 수정된 결과를 새 버전으로 남기고 싶다.

**AC**
- Version 번호가 순차적으로 부여된다.
- 각 Version은 이전 Version과 부모 관계를 가진다.
- 생성 원인이 AI 작업 또는 사용자 변경과 연결된다.

### US-041 변경 비교
**As a** 사용자
**I want** 두 Version의 차이와 변경 이유를 확인하고 싶다.

**AC**
- 변경 전/후 결과를 비교할 수 있다.
- 변경 사유와 연결된 의견을 볼 수 있다.

### US-042 History 조회
**As a** 사용자
**I want** 프로젝트의 작업과 의사결정 과정을 시간순으로 보고 싶다.

**AC**
- 사용자 행동과 AI 작업을 모두 조회할 수 있다.
- Version 생성 이벤트를 History와 연결한다.
- 권한 없는 사용자는 History를 조회할 수 없다.

## Epic E6. Export/운영
### US-050 Export
**As a** 담당자
**I want** 최종 결과를 실제 업무 파일로 내려받고 싶다.

**AC**
- 지원 포맷별 생성 상태를 보여준다.
- 다운로드 파일과 해당 Version을 연결한다.

### US-060 감사 로그
**As a** 운영자
**I want** 중요한 접근과 변경 이벤트를 추적하고 싶다.

**AC**
- 인증, 권한 변경, 파일 접근, AI 요청, Version 생성 등 주요 이벤트가 정책에 따라 기록된다.
- 민감정보 원문은 불필요하게 로그에 남기지 않는다.

P2: 업무 고도화 기능
