# FR-01 인증/권한 v1.0

> **관련 문서**: [기능명세 인덱스](개발문서/기능명세/00_INDEX.md) | [PRD](개발문서/01_PRD.md) | [IA·화면](개발문서/03_IA_FUNCTION_SPEC.md) | [API/DB](개발문서/05_API_DB_SPEC.md)

## 1. 개요

사내 SSO를 통해 사용자를 인증하고 프로젝트 단위 접근권한을 통제한다. (PRD 9절)
자체 계정·비밀번호를 만들지 않고 사내 인증 체계에 위임하며, 인가는 프로젝트 멤버십을 기준으로 한다.

## 2. 동작 상세

- SSO 인증 성공 시 서비스 접속 시점에 사용자 계정과 기본 권한이 생성/조회된다.
- 인증 실패·세션 만료 시 모든 서비스 API가 보호된다(401). Backend가 매 요청마다 세션을 검증한다.
- 리소스 접근 시 프로젝트 멤버십을 검증한다(403). UUID PK는 보조 수단일 뿐 권한 검증을 대체하지 않는다(IDOR).
- LLM Token·credential은 브라우저에 절대 노출하지 않는다. AI 호출은 서버 측 AI Orchestrator만 수행한다.
- 계정 잠금·비밀번호 정책은 사내 SSO 정책에 위임한다.
- ~~❓ **미결**: SSO 연계 방식, 프로젝트 권한 모델(Owner/Editor/Reviewer/Viewer 후보 — 기획안 7-3절). 확정 전 임의 구현 금지~~
- **권한 모델 확정 (2026-09-08)**: `OWNER` / `EDITOR` / `REVIEWER` / `VIEWER` 4단계. 상위가 하위를 포함한다.

| 단계 | 허용 범위 |
|---|---|
| `VIEWER` | 프로젝트·결과물 읽기, 파일·Export 다운로드 |
| `REVIEWER` | + 의견 등록·답글, 책임성/UX 검토 요청 |
| `EDITOR` | + AI 생성·요소 편집, 반영 결정(FR-08·14·15), Export 실행 |
| `OWNER` | + 프로젝트 설정 변경, 멤버 추가·역할 변경·제거, 프로젝트 삭제 |

- 권한 판정은 **Backend 한 곳**에서만 한다. 프론트의 버튼 노출 제어는 편의이며 통제가 아니다.
- ❓ **미결 (계속)**: SSO 연계 방식. Backend는 `AuthenticationProvider` 어댑터로 분리해 두었고 확정 시 구현체만 추가한다 — [결정/미결](개발문서/08_DECISIONS_OPEN_ISSUES.md)
