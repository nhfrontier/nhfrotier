# FR-04 Template v1.0

> **관련 문서**: [기능명세 인덱스](개발문서/기능명세/00_INDEX.md) | [PRD](개발문서/01_PRD.md) | [IA·화면](개발문서/03_IA_FUNCTION_SPEC.md) | [API/DB](개발문서/05_API_DB_SPEC.md)

## 1. 개요

NH 공통 Template과 개인/부서 Template을 구분하고 사용 이력과 버전을 관리한다. (PRD 9절)
새 디자인 시스템을 만들지 않고, 기존 NH 자산을 "업무 자산 계층"으로 제공해 NH다운 결과물을 만든다(기획안 1-2절).

## 2. 동작 상세

- Template은 NH 공통 / 개인·부서 소유로 구분된다. IA 기준 진입: Template(D) → NH Template(D1) / My Template(D2).
- Template은 용도에 따라 **두 유형**으로 나뉜다(`template_type`).
  - `DOCUMENT` — 보고서·PPT 등 문서 양식 (기존 개념)
  - `BRAND_ASSET` — **NH 브랜드 자산.** 로고 SVG, 캐릭터, 컬러 토큰, 서체 규칙, 규격 프리셋, 카드 필수 표기 요소 규칙. [FR-13](개발문서/기능명세/FR-13_브랜드시안제작.md)의 시안 생성이 이 자산만 사용한다
- `BRAND_ASSET`은 AI가 만들지 못하는 그림 요소(로고·캐릭터)를 공급하는 유일한 경로다. AI는 등록된 자산을 **배치만** 하고 새로 그리지 않는다.
- ~~저장소의 `design-system/`(토큰·컴포넌트 자산)은 실제 NH 자산 반입 전까지 `BRAND_ASSET`의 원형이자 검증용 대체재로 쓸 수 있다.~~
  → **디자인 시스템을 복수로 보유하고 생성 시점에 고른다.** 저장소의 `design-systems/` 아래 폴더 하나가 디자인 시스템 하나이며, 선택지 정본은 `design-systems/registry.json`이다. 이것이 `BRAND_ASSET`의 현재 실현체다.

| id | 라벨 | 표면 | 성격 |
|---|---|---|---|
| `allone-bank` | 올원뱅크 (모바일 앱) | 모바일 360×780 | **UX 패턴만 올원뱅크에서 가져왔다.** 색(teal 팔레트)·로고·서체는 실제 CI가 아닌 대체재다. 실제 NH 자산 반입 전까지 검증용이다 |
| `nh-ibz` | NH 기업인터넷뱅킹 (웹) | 웹 1200px | ~~**컬러 토큰은 실제 NH 값**(NH Blue `#0094D9` · NH Green `#00A04E` · navy `#122F50`). 로고·서체·아이콘은 여전히 대체재다~~ → **(2026-09-08) 로고가 공식 CI 로 교체됐다.** 심볼마크·워드마크를 공식 원본에서 벡터 추출해 쓰고(`scripts/trace-nh-ci.mjs`, 원본 대조 IoU 99% 이상 강제), CI 전용색상 4색(`--nh-ci-*`, PANTONE 규격)을 토큰으로 신설했다. 기존 `#0094D9` 등은 ibz 실측 UI 팔레트로 그대로 남는다 — 두 벌을 섞지 않는다. **서체·아이콘·일러스트는 여전히 대체재다** |

  자산의 실체와 대체재 목록은 [design-systems/README.md](design-systems/README.md).
- 선택한 디자인 시스템은 **화면 계획(1단계)과 화면 생성(2단계) 양쪽의 AI 컨텍스트로 전달된다.** 표면(mobile/web)이 화면 흐름을, 토큰이 색·간격·반경을 결정한다 → [FR-05](개발문서/기능명세/FR-05_AI제작.md)
- **(2026-09-08) 시스템의 완성 화면이 생성 프롬프트의 예시로 자동 전달된다.** `_ds_manifest.json`의 `templates[]`가 가리키는 `.dc.html` 본문을 읽어 화면 생성(2단계) 시스템 프롬프트에 넣는다 (`buildExampleScreensSection`). 어느 예시가 지금 만들 화면에 가까운지는 모델이 판단한다.
  - 저장 전 정제(`sanitizeFragment`)를 거치고 `var(--token)`을 실제 값으로 치환해 넣는다. 생성 규칙이 CSS 변수를 금지하므로 예시도 같은 형태여야 한다.
  - 화면 계획(1단계)과 요소 단위 AI 편집에는 넣지 않는다. 각각 화면 목록만 만들고 요소 하나만 고치므로 예시가 불필요하다.
  - 자산을 못 읽으면 예시 절만 빠지고 화면 생성은 그대로 동작한다.
- 선택값은 **버전마다 기록된다**(`mockup_versions.design_system_id`). 같은 프로젝트에서 v1은 모바일, v2는 웹으로 만들 수 있고 어느 시스템으로 만든 버전인지 화면에 표시된다.
- 요소 단위 AI 편집도 그 버전을 만든 디자인 시스템을 그대로 쓴다. 편집 결과만 다른 팔레트로 나오지 않게 하기 위함이다.
- 디자인 시스템을 추가하려면 `design-systems/<id>/`에 폴더를 넣고 `registry.json`에 한 줄 더한다. 읽는 것은 `<id>/_ds_manifest.json`의 `tokens[]`·`templates[]` 두 개뿐이라 코드를 고칠 일이 없다. `templates[]`는 이름만이 아니라 `entryPath`가 가리키는 HTML 본문까지 읽는다.
- **디자인 시스템은 고르는 순간 진입이다.** Template 화면의 시스템 카드는 선택 스위치가 아니라 링크이며, 누르면 그 시스템이 **선택된 채로 화면 만들기**에 들어간다. ~~화면 템플릿 카드의 "이 Template로 시작"도 같은 자리로 가되 참고 템플릿이 함께 지정된다.~~ → **(2026-09-08) 참고 템플릿을 고르는 단계를 없앱다.** 고르는 것은 디자인 시스템 하나뿐이고, 그 시스템의 **완성 화면을 전부** 생성 프롬프트에 예시로 넣는다(아래 항목). 화면 템플릿 카드는 제거됐다.
  - 정적 목업은 `screen-brief.html?ds=<id>`로 넘긴다. ~~`&tpl=<slug>`~~ — 이 파라미터는 폐기했다.
  - Next.js 앱은 생성이 프로젝트 안에서만 가능하므로(`mockup_versions`가 프로젝트에 매달린다) **프로젝트를 고르는 단계**를 한 번 거쳐 `/projects/{id}?tab=generate&ds=<id>`로 들어간다. 진행 중인 프로젝트에 이어 붙이는 경로를 겸한다.
- 카드에 표시되는 대표 색·토큰 수·컴포넌트 수·템플릿 목록은 손으로 적지 않는다. `_ds_manifest.json`에서 뽑는다(`describeDesignSystem`). 시스템을 추가해도 화면 문구를 따라 고칠 일이 없다.
- (❓ NH 실제 브랜드 자산의 반입 경로와 관리 주체 미결 — [결정/미결](개발문서/08_DECISIONS_OPEN_ISSUES.md))
- Template 버전을 선택할 수 있다. 버전은 `template_versions`로 관리한다(TEMPLATE 1:N TEMPLATE_VERSION).
- 사용자가 선택한 Template은 AI 요청 컨텍스트로 전달된다 → [FR-05](개발문서/기능명세/FR-05_AI제작.md)
- Template 사용 이력을 남겨 재사용률(성공 지표)을 측정할 수 있게 한다.
- 후속 고도화: Template 추천, Marketplace(PRD 4절 후속·P5).
