# FR-06 협업 v1.0

> **관련 문서**: [기능명세 인덱스](개발문서/기능명세/00_INDEX.md) | [PRD](개발문서/01_PRD.md) | [IA·화면](개발문서/03_IA_FUNCTION_SPEC.md) | [API/DB](개발문서/05_API_DB_SPEC.md)

## 1. 개요

결과물 또는 특정 영역에 의견을 남기고 담당자를 지정할 수 있어야 한다. (PRD 9절)
여러 채널로 분산되던 사업·테크·디자인·준법 의견을 하나의 결과물 위에서 취합한다(기획안 1-1절).

## 2. 동작 상세

- 일반 의견과 특정 영역/요소에 대한 의견을 구분해 등록한다.
  - **(2026-09-05 구체화)** "요소"는 화면 목업 안의 **임의의 HTML 요소**(버튼·입력창·카드 등)다. 디자인시스템 컴포넌트 단위가 아니다.
  - 앵커는 `(화면, 요소 id)` 쌍으로 저장한다(`comments.screen_id` · `comments.nh_id` · `comments.anchor_status`). 요소 id는 AI 출력이 아니라 **서버가 저장 시점에 부여**한다.
  - 화면에서는 지목한 요소 위에 번호 핀으로 겹쳐 보여준다. ([03_IA_FUNCTION_SPEC.md](../03_IA_FUNCTION_SPEC.md) S03)
  - **화면을 다시 만들면 요소 id가 바뀐다.** 텍스트·구조·순서 지문을 대조해 다시 잇고, 못 이으면 **삭제하지 않고** `orphaned`로 남겨 사람이 요소를 골라 다시 붙인다. "완벽히 안정된 id"는 만들 수 없다는 것을 전제로 한 설계다.
- **(2026-09-08 추가) 의견은 스레드다.** 뿌리 의견에 답글을 달 수 있다(`comments.parent_id`).
  - **답글은 자기 앵커를 갖지 않는다.** 스레드가 가리키는 요소는 뿌리의 것이고, 답글마다 앵커를 주면 같은 요소에 핀이 여러 개 겹친다.
  - 스레드는 **한 겹까지만** 둔다. 답글의 답글은 뿌리로 평탄화한다 — 들여쓰기가 깊어질수록 어느 요소를 가리키는 논의인지 흐려진다.
- **(2026-09-08 추가) 의견을 AI에게 보내면 그 요소만 다시 만든다.** 작성 영역의 `AI에게 보내기`가 의견을 저장한 뒤 그 내용을 프롬프트로 [FR-05](FR-05_AI제작.md)의 요소 단위 재생성을 호출한다.
  - **의견을 먼저 저장한다.** AI 호출이 실패해도 사람이 쓴 말은 남아야 한다.
  - 결과는 `element_patches.comment_id`로 그 의견에 연결되어 **스레드 안에 결과 카드로 되돌아온다.** AI의 답을 `comments` 행으로 만들지 않는 이유는 [ARCHITECTURE.md 12절](../../docs/architecture/ARCHITECTURE.md)과 같다 — 사람 댓글 테이블에 AI용 필드를 붙이면 삭제·해결 토글의 의미가 달라진다. **저장은 분리하고 합치는 것은 화면에서만 한다.**
  - AI에게 보내려면 가리키는 요소가 있어야 한다. 요소를 고르지 않았고 답글도 아니면 이 경로는 막힌다 — 무엇을 고칠지 알 수 없기 때문이다.
  - 반영 결과는 카드의 `되돌리기`로 취소한다(soft revert, `reverted_at`). 되돌려도 행은 남아 편집 이력에 보인다.
- 작성자와 작성시각이 기록된다. 담당자를 지정할 수 있고, 알림 확장 포인트를 둔다.
- 의견은 단순 코멘트로 끝나지 않는다 — 상태 전이 `OPEN → REVIEWED → ACCEPTED / REJECTED / DEFERRED`를 가지며(03 상태 모델), `comments → review_items → review_decisions → versions`로 연결된다 → [FR-07](개발문서/기능명세/FR-07_AI의견취합.md), [FR-08](개발문서/기능명세/FR-08_반영결정.md)
- 의견 조회·작성 시 프로젝트 멤버십을 검증한다(IDOR).
- 프로토타입에서 검증된 UX: 버전 단위 의견 스레드, 본인 작성 건만 삭제, 미선택 상태 가드 문구. (프로토타입의 프로젝트 단위 팀 채팅(PFR-09)은 정본 FR에 미반영 — ❓ 제품 채택 여부 협의 필요)
