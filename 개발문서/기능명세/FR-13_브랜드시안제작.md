# FR-13 브랜드 시안 제작 v1.0

> **관련 문서**: [기능명세 인덱스](개발문서/기능명세/00_INDEX.md) | [PRD](개발문서/01_PRD.md) | [IA·화면](개발문서/03_IA_FUNCTION_SPEC.md) | [화면 상세](개발문서/09_UI_SPEC_브랜드시안.md) | [API/DB](개발문서/05_API_DB_SPEC.md)

## 1. 개요

카드 실물·홍보물의 **컨셉 시안**을 AI로 생성하고, 여러 방향을 나란히 놓고 관련 담당자가 방향을 합의하도록 지원한다. (PRD 9절)

**이 기능이 하는 일과 하지 않는 일을 먼저 못박는다.**

| 한다 | 하지 않는다 |
|---|---|
| 방향·톤·레이아웃·문구를 눈으로 비교할 수 있게 만든다 | 인쇄에 넘길 최종 파일을 만들지 않는다 |
| 기존 NH 자산(로고·컬러·서체)을 **배치**한다 | 새 디자인 시스템을 만들지 않는다 (PRD 5절 비범위 유지) |
| 규격·자산·용도가 고정된 업무 산출물을 만든다 | 범용 디자인 생성기가 아니다 ([개발문서 README](개발문서/README.md)) |
| 방향 결정을 Version·History에 남긴다 | AI가 최종안을 확정하지 않는다 ([결정 Q2](개발문서/08_DECISIONS_OPEN_ISSUES.md)) |

산출물 수준은 **컨셉 시안**이다. 인쇄 규격(mm·CMYK·재단선·해상도)은 다루지 않는다. 실제 제작은 디자인 조직 또는 대행사가 이어받는다.

### 기술적 전제 — 이미지는 생성되지 않는다

LLM의 출력은 텍스트다. 시안은 **고정 비율 캔버스 위의 HTML/CSS + 인라인 SVG**로 그린다.

- 표현 가능: 배경 그라데이션, 도형, 패턴, 타이포그래피, 레이아웃, 색 조합
- **표현 불가: 로고·캐릭터·일러스트·사진.** 이 소재는 AI가 만들지 못한다.

따라서 소재는 **브랜드 자산 라이브러리에 사전 등록된 것만** 쓰고, AI는 그것을 배치하는 역할만 맡는다 → [FR-04](개발문서/기능명세/FR-04_템플릿.md)

## 2. 동작 상세

### 2-1. 산출물 유형과 규격 프리셋

MVP 지원 유형은 **카드 실물**과 **홍보물(포스터/배너)** 2종이다. 컨셉 시안이므로 물리 치수가 아니라 **비율과 안전영역**만 사용한다.

| 프리셋 ID | 이름 | 비율 | 비고 |
|---|---|---|---|
| `CARD_H` | 카드 (가로형) | 1.586 : 1 | ISO/IEC 7810 ID-1 비율 |
| `CARD_V` | 카드 (세로형) | 1 : 1.586 | |
| `POSTER_A` | 포스터 (A 계열 세로) | 1 : 1.414 | A2·A3 공용 비율 |
| `BANNER_SQ` | 디지털 배너 (정사각) | 1 : 1 | SNS·행내 게시 |

프리셋은 코드에 넣지 않고 `templates`(BRAND_ASSET 유형)의 데이터로 관리한다. 유형을 늘릴 때 코드를 고치지 않게 한다.

### 2-2. 입력

- **브리프**: 상품·캠페인명 / 타겟 / 전달할 느낌(키워드) / 반드시 들어갈 문구
- **브랜드 자산 선택**: 로고·컬러 토큰·서체 규칙 등 → [FR-04](개발문서/기능명세/FR-04_템플릿.md)
- **참고자료 선택**: 기존 업로드 파일 중 참조 대상 지정 → [FR-03](개발문서/기능명세/FR-03_참고자료.md)

### 2-3. 3안 동시 생성

- AI 작업은 **[FR-05](개발문서/기능명세/FR-05_AI제작.md)의 비동기 Job 구조를 그대로 재사용**한다. 새 파이프라인을 만들지 않는다.
- `ai_jobs.job_type = BRAND_CONCEPT`으로 문서·화면 생성과 구분한다.
- 한 Job이 **서로 다른 방향의 시안 3개**를 만든다. `ai_job_outputs` 3행으로 저장하고 `variant_no`(1·2·3)로 구분한다.
- 각 시안에 `variant_label`(예: "정통·신뢰형", "젊고 경쾌한", "프리미엄")을 붙여 **왜 다른 방향인지**를 화면에서 설명할 수 있게 한다. 비디자이너가 시각적 차이를 언어로 다룰 수 있어야 논의가 된다.
- 상태 전이·실패 처리·재시도·중복 제출 방지는 FR-05와 동일하다.
- (❓ 3안 생성이 LLM 호출 3회인지 1회인지 미결 — AI 동시 호출 제한·최대 토큰과 직결. [결정/미결](개발문서/08_DECISIONS_OPEN_ISSUES.md))

### 2-4. 선택과 Version — 3안은 후보이지 Version이 아니다

- **3안이 생성되는 시점에는 Version을 만들지 않는다.** 아직 후보이기 때문이다.
- 사용자가 **하나를 고르는 순간** `versions` 1행이 생성된다. `source_type = AI_GENERATION`, `source_job_id`로 Job과 연결한다 → [FR-09](개발문서/기능명세/FR-09_버전관리.md)
- 고른 뒤 대화로 수정하면 `source_type = AI_REVISION`으로 새 Version이 이어진다.
- 이렇게 해야 Version 목록이 채택되지 않은 후보로 오염되지 않고, **"왜 이 방향을 골랐는가"가 선택 시점의 History로 남는다** → [FR-10](개발문서/기능명세/FR-10_히스토리.md)

### 2-5. 의견과 반영 결정

- 각 시안에 개별 의견을 등록할 수 있다 → [FR-06](개발문서/기능명세/FR-06_협업의견.md)
- 의견 취합·반영 결정은 기존 흐름을 그대로 쓴다 → [FR-07](개발문서/기능명세/FR-07_AI의견취합.md) · [FR-08](개발문서/기능명세/FR-08_반영결정.md)
- AI 제안은 자동 확정되지 않는다. 방향 선택도 반영 결정도 사람이 한다.

### 2-6. 보안

생성 HTML은 **[FR-05](개발문서/기능명세/FR-05_AI제작.md)와 완전히 동일한 정책**을 따른다. 본 기능에서 별도 정책을 만들지 않는다.

- AI 생성 HTML은 신뢰할 수 없는 입력으로 취급한다.
- 샌드박스 iframe으로 격리 렌더링한다. `allow-same-origin`과 `allow-scripts`를 동시에 부여하지 않는다.
- 상세: [SECURITY_CHECKLIST.md](docs/guidelines/SECURITY_CHECKLIST.md) 4절 (❓ 최종 정책 미결)

## 4. 관련 API

기존 AI Job API를 재사용한다. **신규 엔드포인트를 만들지 않는다.**

| Method | Path | 용도 |
|---|---|---|
| POST | `/api/v1/projects/{projectId}/ai/jobs` | Job 생성 (`job_type = BRAND_CONCEPT`) |
| GET | `/api/v1/ai/jobs/{jobId}` | 상태 조회 · 3안 결과 조회 |
| POST | `/api/v1/ai/jobs/{jobId}/retry` | 재시도 |
| GET | `/api/v1/templates` | 브랜드 자산 목록 (`template_type = BRAND_ASSET`) |

오류: 429(호출 제한), 502/504(LLM 연계). 정본: [05_API_DB_SPEC.md](개발문서/05_API_DB_SPEC.md)
