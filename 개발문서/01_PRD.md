# NH뚝딱협업스튜디오 PRD v1.0

## 1. 제품 정의
**제품명:** NH뚝딱협업스튜디오
**한 줄 정의:** NH 업무 맥락과 승인된 AI를 활용해 아이디어를 결과물로 만들고, 관련 담당자의 협의·의사결정·변경 이력을 하나의 흐름으로 관리하는 내부 업무 제작 플랫폼.

## 2. 배경과 문제
업무 담당자는 보고서, PPT, 웹/앱 화면 시안, 카드·홍보물 시안 등을 반복 작성·수정하고, 사업/테크/디자인/준법 등 여러 조직의 의견을 메일·메신저·회의 등 여러 경로에서 취합한다. 범용 AI는 초안 생산성은 높이지만 NH 업무양식과 내부 참고자료를 매번 설명해야 하고, 내부 자료 활용에는 보안·사용범위 제약이 있다.

## 3. 제품 목표
- 아이디어를 문서·웹·앱 결과물로 빠르게 구체화
- NH Template과 내부 업무 자산의 재사용성 확보
- 협의 내용을 한 곳에 모아 재작업과 협의 시간을 줄임
- AI가 의견을 합의/이견/추가확인으로 정리하도록 지원
- 담당자가 반영 여부를 직접 결정하고 결과물을 새 버전으로 생성
- Version과 History를 통해 변경 이유와 의사결정 과정을 추적
- 프로젝트별 결과물과 업무 노하우를 조직 자산으로 축적

## 4. 범위
### MVP 포함
- 사내 SSO 로그인 및 사용자/권한
- 프로젝트 생성/조회/공유/멤버 관리
- 참고자료 업로드 및 파일 메타데이터 관리
- NH Template / 나만의 Template 선택
- AI Chat 및 기본 결과 생성
- 문서/웹·앱 시안 초안 생성
- 브랜드 시안(카드 실물·홍보물) 초안 생성 및 3안 비교·선택
- LLM API 인증/호출을 위한 AI Orchestrator
- 댓글 및 협업 의견 등록
- AI 의견 요약(합의/이견/추가확인)
- 생성 결과물의 책임성 검토(표현·차별 / 금융소비자보호 / 다크패턴 / 접근성) 및 담당자 결정
- 논의와 화면을 함께 읽는 UX 리스크 검토(누적·중단·예외상황·되돌리기·사용맥락·빠진 이해관계자) 및 담당자 결정
- 반영할 의견 선택 및 AI 수정 요청
- Version 생성/조회/비교
- History 기록

### 후속 고도화
- PPTX/DOCX/HWPX/HTML Export 고도화
- 내부 업무기준/VOC 연계
- RAG 기반 검색·근거 제시
- 승인/결재 워크플로우 연계
- 업무사례/Template 추천
- 프로젝트 분석 및 협업 지표
- AI Agent 기반 반복 업무 자동화

## 5. 비범위
- 자체 LLM 개발/학습
- 새로운 디자인 시스템의 전면 구축
  - FR-13 브랜드 시안 제작은 이에 해당하지 않는다. 새 디자인 체계를 세우는 것이 아니라 **기존 NH 자산을 배치해 컨셉 시안을 만드는 것**이다. 자산의 정본은 기존 NH 디자인 자산이며 본 제품은 그것을 소비만 한다.
- 카드·홍보물의 인쇄용 최종 파일 제작 (인쇄 규격·CMYK·재단선·해상도) — FR-13은 컨셉 시안까지만 다룬다
- 사용자 브라우저의 직접 LLM 호출
- 기관 전체 문서 저장소를 초기부터 통합하는 작업
- 자동 승인 또는 준법 판단의 완전 자동화
  - FR-14 책임성 검토는 이에 해당하지 않는다. AI는 **"준법 검토가 필요해 보인다"까지만** 말하고 적법성을 판정하지 않으며, Export·공유를 차단하지 않는다. 판단이 필요한 건은 `준법 검토 요청` 결정으로 사람에게 넘긴다.
  - FR-15 UX 리스크 검토도 이에 해당하지 않는다. AI는 **"이 결정들이 합쳐지면 이런 결과가 됩니다"까지만** 말하고 설계의 좋고 나쁨을 판정하지 않으며, 특정 의견이나 작성자를 지목해 틀렸다고 말하지 않는다. 생성·Export·공유를 차단하지 않는다.

## 6. 핵심 사용자
### U1 업무 담당자
아이디어를 정리하고 산출물을 만들어야 하는 실무자.
### U2 협업 검토자
사업/테크/디자인/준법 등 결과물을 검토하고 의견을 남기는 사용자.
### U3 프로젝트 관리자
프로젝트 멤버, 결과물, 협의상태와 History를 관리하는 사용자.
### U4 운영 관리자
Template, 권한, 시스템 정책과 운영 로그를 관리하는 역할.

## 7. 핵심 사용자 여정
프로젝트 생성 → 자료/Template 선택 → AI로 초안 생성 → 검토자 초대 → 결과물에 의견 등록 → AI 의견 취합 → 담당자가 반영할 의견 선택 → AI 수정 → 새 Version 생성 → History 축적 → 최종 파일 Export

## 8. 성공 지표
초기에는 정량 KPI보다 사용성 검증 지표를 우선한다.
- 프로젝트 최초 결과물 생성 성공률
- AI 생성 결과의 사용자 채택률
- 의견 취합 후 재작업 횟수 감소
- 프로젝트당 협의 완료까지의 평균 소요시간
- Version 간 변경사항 추적 가능 비율
- Template 재사용률

### FR-12 감사 추적
주요 인증·권한·변경·AI 호출 관련 이벤트를 감사 대상으로 남길 수 있어야 한다.
상세: [FR-12 감사 추적](개발문서/기능명세/FR-12_감사추적.md)

### FR-13 브랜드 시안 제작
카드 실물·홍보물의 컨셉 시안을 서로 다른 방향 3안으로 생성하고, 담당자가 하나를 선택해 방향을 확정한다. 선택 시점에 Version이 생성된다.
상세: [FR-13 브랜드 시안 제작](개발문서/기능명세/FR-13_브랜드시안제작.md)

### FR-14 책임성 검토
생성된 화면·산출물에서 표현·차별, 금융소비자보호, 다크패턴, 접근성 축의 문제 지점을 근거와 함께 제시하고, 담당자가 반영/보류/반려/준법 검토 요청을 선택한다. **AI는 판정하지 않는다.**
상세: [FR-14 책임성 검토](개발문서/기능명세/FR-14_책임성검토.md) · 규칙 정본: [RESPONSIBLE_DESIGN.md](docs/guidelines/RESPONSIBLE_DESIGN.md)

### FR-15 UX 리스크 검토
담당자가 요청하면 전 화면의 목업과 의견 전문을 함께 읽고, 개별 의견으로는 타당하지만 합쳐지면 사용자가 불편해지는 지점을 근거와 함께 의견 흐름에 올린다. 담당자가 반영/보류/반려를 선택한다. **AI는 판정하지 않으며, 사람의 의견을 대체하지 않는다.**
상세: [FR-15 UX 리스크 검토](개발문서/기능명세/FR-15_UX리스크검토.md) · 렌즈 정본: [USABILITY_REVIEW.md](docs/guidelines/USABILITY_REVIEW.md)

## 10. 비기능 요구사항
- 내부 Linux 서버 + Docker 배포 가능 구조
- 모든 외부/AI 연계는 서버 측에서 수행
- LLM Token/Secret은 코드/프론트에 노출하지 않음
- API timeout/retry/error handling 제공
- 장시간 AI 작업은 비동기 처리 가능
- 파일과 DB 데이터를 분리 저장
- API/DB/File 권한을 최소권한으로 설계
- 운영 로그와 감사 로그를 구분
- 향후 K8s 전환이 가능한 컨테이너 구조 유지

## 11. MVP Definition of Done
- 사용자 로그인 후 프로젝트를 생성할 수 있다.
- 프로젝트 자료를 업로드하고 AI 요청에 선택해서 사용할 수 있다.
- 승인된 LLM API로 생성 요청을 보내고 결과를 저장할 수 있다.
- 협업자가 결과물에 의견을 남길 수 있다.
- AI가 의견을 정리하고 담당자가 반영 여부를 선택할 수 있다.
- 반영 결과로 새 Version이 생성된다.
- Version과 History에서 변경 원인과 작업 이력을 확인할 수 있다.
- 운영환경에서 재현 가능한 Docker 배포가 가능하다.
